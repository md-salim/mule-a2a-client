What is A2A Protocol?

🎯 Definition

A2A (Agent-to-Agent) is an open protocol that enables AI agents to communicate with each other securely and reliably using standard HTTP + JSON-RPC.

🏗️ Key Concepts

  • Task — A unit of work assigned to an agent
  • Message — Input sent to the agent
  • Artifact — Output produced by the agent
  • Agent Card — Agent's capability manifest

📡 Communication Bindings

  • JSON-RPC 2.0 — Method-based RPC over HTTP POST
    POST /agent/rpc
  • HTTP+JSON — REST-style binding
    POST /agent/rest
  • SSE (Server-Sent Events) — Real-time streaming
    Accept: text/event-stream

🔄 Task Lifecycle

SUBMITTED → WORKING → COMPLETED | CANCELED | FAILED

🖥️ A2A Server Role (mule-a2a-server)

Hosts the A2A agent. Listens for incoming A2A protocol requests via JSON-RPC or HTTP+JSON, processes them using Gemini LLM + MCP tools, and returns structured task results.

📱 A2A Client Role (mule-a2a-client)

Acts as a REST facade. Exposes clean HTTP endpoints for consumers and forwards requests to the A2A server using the A2A connector's client operations.

Operations

Operations used in Mule flows that expose the A2A agent capability — listeners, task management, artifact updates, and push notifications.

🎧 a2a:task-listener

What it does

The primary listener that receives ALL A2A protocol operations (SendMessage, GetTask, CancelTask, ListTasks, SubscribeToTask). Acts as the main entry point for the A2A agent flow.

Key Attributes

  • attributes.taskId — Unique task ID
  • attributes.contextId — Conversation context
  • attributes.operationName — Which A2A method was called
  • payload — MessageSendParams or operation params

Triggered By

SendMessage, SendStreamingMessage, GetTask, CancelTask, ListTasks, SubscribeToTask

<a2a:task-listener config-ref="A2A_Server_Config"/> <choice> <when expression="#[attributes.operationName == 'SendMessage']"> when> <when expression="#[attributes.operationName == 'GetTask']"> when> <otherwise> otherwise> choice>
5

⚡ a2a:on-async-request-listener

What it does

Handles the initial handshake for SendStreamingMessage. It fires immediately when a streaming request arrives and MUST return an initial Task with TASK_STATE_SUBMITTED. This seeds the SSE stream so events can flow.

⚠️ Critical Rule

Without this listener, SendStreamingMessage will NOT work. The connector needs this to open the SSE channel before the main task-listener processes the request in the background.

When it fires

Only for SendStreamingMessage requests.

<flow name="async-request-flow"> <a2a:on-async-request-listener config-ref="A2A_Server_Config"/> <ee:transform> <ee:set-payload> { task: { id: attributes.taskId, contextId: attributes.contextId, status: { state: "TASK_STATE_SUBMITTED" } } } ee:set-payload> ee:transform> flow>
6

📊 a2a:update-task-status

What it does

Updates the task's current state and optionally attaches a status message. Used throughout agent processing to communicate progress: WORKING → COMPLETED / FAILED / CANCELED.

Valid State Transitions

SUBMITTED WORKING COMPLETED CANCELED FAILED
<a2a:update-task-status config-ref="A2A_Server_Config"> <a2a:status-content> a2a:status-content> a2a:update-task-status>
7

📦 a2a:update-task-artifact

What it does

Publishes the agent's result as an Artifact — the actual data output of the task. An artifact contains one or more Parts (text, data, or file). For streaming, each artifact call fires an SSE event to the client.

Part Types

  • text — Plain text or JSON string
  • data — Structured JSON object with mimeType
  • file — File content with bytes or URI

When to use

After the agent completes its work (MCP tool call, LLM response, etc.). Called BEFORE update-task-status COMPLETED.

<a2a:update-task-artifact config-ref="A2A_Server_Config"> <a2a:artifact-content> a2a:artifact-content> a2a:update-task-artifact>
8

🏷️ a2a:set-task-metadata

What it does

Attaches custom key-value metadata to a task. Useful for storing context about how the task was processed — tool name, model used, processing time, etc. This metadata is retrievable via GetTask.

Common Use Cases

  • Recording which MCP tool was invoked
  • Storing the LLM model version used
  • Audit trail (processedAt timestamp)
  • Debugging context for failed tasks

Key Parameter

taskId — required as an XML attribute (not from context)

<a2a:set-task-metadata config-ref="A2A_Server_Config" taskId="#[vars.taskId]"> <a2a:metadata> a2a:metadata> a2a:set-task-metadata>
9

🔔 a2a:send-push-notification

What it does

Sends an HTTP POST callback to the registered push notification URL with the task's current status. Allows clients to receive real-time updates without polling.

⚡ How Push URL is Set

Two ways to register a push URL:

  • In SendMessage request — Pass pushUrl in the client request body → mule-a2a-client includes it in configuration.taskPushNotificationConfig
  • Explicit API call — Client calls CreateTaskPushNotificationConfig API

Error Handling

Always wrap in a choice or try — if no URL registered, the operation raises A2A:PUSH_NOTIFICATION_UNSUPPORTED.

<choice> <when expression="#[vars.pushUrl != null]"> <a2a:send-push-notification config-ref="A2A_Server_Config"> <a2a:notification-message> a2a:notification-message> a2a:send-push-notification> when> <otherwise> <logger message="push skipped"/> otherwise> choice>

🔒 Task Authorizer + Push Config Listeners

🛡️ a2a:task-authorizer-listener

An interceptor gate that fires automatically before task-management operations: GetTask, CancelTask, SubscribeToTask, ListTasks, and push config CRUD.

Use it to validate the caller's identity or ownership. Raise an error to deny; do nothing to allow.

NOT called for: SendMessage, SendStreamingMessage
<a2a:task-authorizer-listener config-ref="A2A_Server_Config"/> // payload = task params // attributes.operationName = op type // Raise error to deny access

📬 a2a:push-notification-config-listener

Fires when a client calls CreateTaskPushNotificationConfig. Allows the server to validate the callback URL before the connector stores it.

If the flow completes successfully → config is registered. Raise an error to reject the URL.

payload.url — the callback URL to validate
<a2a:push-notification-config-listener config-ref="A2A_Server_Config"/> <choice> <when expression="#[payload.url != null]"> // Valid — connector auto-stores when> <otherwise> <raise-error type="APP:INVALID_URL"/> otherwise> choice>

📋 a2a:get-tasks & a2a:get-tasks-by-context

a2a:get-tasks

Retrieves a batch of tasks from the server's internal Object Store by their IDs. Returns found tasks + list of IDs that were not found.

  • Input — List of task IDs (via payload)
  • historyLength — Number of history entries to include
  • Output — { tasks: [...], nonExistentTaskIds: [...] }
<ee:transform> <ee:set-payload> [payload.id default vars.taskId] ee:set-payload> ee:transform> <a2a:get-tasks config-ref="A2A_Server_Config" historyLength="#[5]"/>

a2a:get-tasks-by-context

Retrieves all tasks belonging to a specific contextId. Used for SubscribeToTask — fetches the context so the SSE stream knows what to replay.

  • contextId — Groups related tasks in a conversation
  • Output — All tasks for that context
<a2a:get-tasks-by-context config-ref="A2A_Server_Config" contextId="#[attributes.contextId default vars.contextId]"/>

Part 2

A2A Client
Operations

Operations used in Mule flows that call an A2A agent server — discovery, messaging, task management, and push notification configuration.

13

🃏 a2a:get-card  &  💬 a2a:send-message

a2a:get-card

Fetches the Agent Card from the server's /.well-known/agent-card.json. Returns the agent's name, description, capabilities, supported interfaces, and available skills.

Use this to discover what an agent can do before sending messages.

<a2a:get-card config-ref="A2A_Client_Config"/> // payload = AgentCard JSON // payload.name, payload.skills, etc.

a2a:send-message

Blocking call to the agent. Waits for the task to reach a terminal state and returns the completed Task object with artifacts. Ideal for synchronous use cases.

  • configuration.taskPushNotificationConfig — optional push URL
  • contextId — continue existing conversation
<a2a:send-message config-ref="A2A_Client_Config"> <a2a:message> a2a:message> a2a:send-message>
14

📡 a2a:send-stream-message  &  🔄 a2a:subscribe-to-task

a2a:send-stream-message

Non-blocking streaming call. The server returns SUBMITTED immediately and sends SSE events as processing progresses. The client receives a live stream of status updates and artifacts.

  • SUBMITTED → WORKING → artifact → COMPLETED
  • Requires on-async-request-listener on server
<a2a:send-stream-message config-ref="A2A_Client_Config"> <a2a:stream-message> a2a:stream-message> a2a:send-stream-message> // payload = SSE stream // Set response Content-Type: text/event-stream

a2a:subscribe-to-task

Re-connect to an existing task's SSE stream. If the connection was dropped mid-task, the client can re-subscribe and receive buffered events from where it left off.

  • Task must be in WORKING state
  • Receives buffered + new events
<ee:transform> <ee:set-payload> { id: vars.taskId } ee:set-payload> ee:transform> <a2a:subscribe-to-task config-ref="A2A_Client_Config"> <a2a:task-id-params> a2a:task-id-params> a2a:subscribe-to-task>
15

📋 a2a:list-tasks  |  a2a:get-task  |  a2a:cancel-task

Client

a2a:list-tasks

Lists all tasks on the agent server. Supports filtering by contextId, pageSize, and historyLength. Returns a paged array of tasks.

<a2a:list-tasks config-ref="A2A_Client_Config"> <a2a:list-tasks-params> a2a:list-tasks-params> a2a:list-tasks>
Client

a2a:get-task

Retrieves a single task by ID with its full history, status, and artifacts. Specify historyLength to control how many history entries to include.

<a2a:get-task config-ref="A2A_Client_Config"> <a2a:task-query> a2a:task-query> a2a:get-task>
Client

a2a:cancel-task

Requests the agent server to cancel a running task. The server transitions the task to TASK_STATE_CANCELED and returns the updated task object.

<a2a:cancel-task config-ref="A2A_Client_Config"> <a2a:task-id> a2a:task-id> a2a:cancel-task>

🔔 Push Notification Client Operations

Client

a2a:create-push-notification-config

Registers a webhook callback URL for a specific task. The server will POST status updates to this URL as the task progresses.

<a2a:create-push-notification-config config-ref="A2A_Client_Config"> <a2a:task-push-notification-config> a2a:task-push-notification-config> a2a:create-push-notification-config>
Client

a2a:list-push-notification-configs

Lists all registered push notification configs for a task. Returns an array of configs with their IDs and URLs.

<a2a:list-push-notification-configs config-ref="A2A_Client_Config"> <a2a:list-push-config-params> a2a:list-push-config-params> a2a:list-push-notification-configs>
Client

a2a:get-push-notification-config

Retrieves a specific push notification config by its ID. Useful for verifying that the registration succeeded.

<a2a:get-push-notification-config config-ref="A2A_Client_Config"> <a2a:get-push-config-params> a2a:get-push-config-params> a2a:get-push-notification-config>
Client

a2a:delete-push-notification-config

Removes a push notification config by its ID. The server will no longer send webhook callbacks to that URL for the task.

<a2a:delete-push-notification-config config-ref="A2A_Client_Config"> <a2a:get-push-config-params> a2a:get-push-config-params> a2a:delete-push-notification-config>
